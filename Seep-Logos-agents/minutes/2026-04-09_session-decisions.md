### トピック2: メモリ仕様の理解とCLAUDE.mdへの保護ルール追加

#### 依頼内容
ユーザーより「memoryディレクトリのファイルをClaudeが削除したのではないか」との指摘があった。メモリ仕様に関する詳細調査と、削除防止ルールの確立を依頼した。

#### 対応内容

**調査結果：**
- メモリの保存場所は Claude Code の仕様どおり `~/.claude/projects/[プロジェクトパス]/memory/` に保存される
- git管理外なのも意図的な設計（プロジェクトリポジトリを汚さない個人設定）
- Claude Code のメモリ仕様に「古い・誤ったメモリは削除せよ」という指示が含まれており、Claude が善意で削除できてしまう設計

**問題認識：**
メモリの自動削除は設計上の仕様だが、ユーザーの意図と乖離している。ユーザーが「永続的に保持すべき指示」と「セッション間参照用の一時情報」を区別する必要がある。

#### 主な出力・決定事項

1. **用途別の正しい使い分けを確認**
   | 目的 | 正しい場所 | 削除可能性 |
   |---|---|---|
   | Claude が絶対に消せない永続指示 | `CLAUDE.md` | 削除不可 |
   | セッション間で Claude が参照する文脈・好み | `memory/` | 削除ルール変更前は削除される可能性があった |

2. **CLAUDE.md にメモリ保護ルールを追加（実装完了）**
   - 「コード編集ルール」の直前に新セクション「メモリ管理ルール（必須）」を挿入
   - 内容：`memory/` 内ファイルは削除禁止。更新・追記のみ許可。古い・誤りと判断した場合も削除せず上書き修正すること。

3. **メモリ削除仕様の改善**
   - 設計上の仕様問題を認識。今後は memory/ ファイルを削除しない運用へ変更

- 根拠：「じわじわと浸透するのにハッキリとした線は違います」（プロデューサー、2026-03-25）
