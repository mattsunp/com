### 2. マニュアルの対象・方向性
- 対象: Web デザイン担当者（社内スタッフ・業務委託）
- **主軸はWebデザインの仕事の流れ**。DESIGN.md はその成果物フォーマット、AI（web-coder）はその工程のひとつという位置づけ
- **Seep Logos らしさは出さない**。汎用的なWebデザインマニュアルとして作成する（Seep Logos固有ルールは別途上書きする運用を想定）

### 3. 構成（確定）
| セクション | 内容 |
|---|---|
| 1. Webデザイナーの役割 | 汎用的なデザイン哲学（目的を視覚で伝えること） |
| 2. 仕事一覧 | 設計・ドキュメント化・確認フィードバック・日常業務 |
| 3. 案件の進め方 | 5ステップ（①把握→②言語化→③設計→④DESIGN.md→⑤確認） |
| 4. DESIGN.md の書き方 | 仕様書としての位置づけ・§1 の書き方・良い例/悪い例 |
| 5. 品質チェックリスト | 設計チェック・DESIGN.md チェック |
| 6. 参考資料の使い方 | 収集済み84ブランドの活用法 |

### 4. フィードバックによる主な修正履歴
1. **「§2が概念的」** → 具体的な作業タスクの列記に変更
2. **「AI入力の手順書になっている」** → Webデザインの仕事の流れを主軸に全体再構成
3. **「工程が多すぎて尻込みする」** → 13ステップ→5ステップに簡略化。「AIが実装を担うから方向性に集中すればいい」という安心感を追加
4. **「Seep Logosらしさは出さず汎用マニュアルに」** → 没入感・浸透（Seep）・暗色背景必須などのSeep Logos固有ルールを除去
