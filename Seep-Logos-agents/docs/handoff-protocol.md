# Handoff Protocol

> 対象: Claude Code と Codex 間の引き継ぎ
> 目的: セッションをまたいでも記憶違いと重要事項の欠落を減らす
> 最終更新: 2026-04-12

---

## 1. この文書の目的

AI 間の内部記憶は完全には共有されない。
そのため、`Claude Code` から `Codex`、または `Codex` から `Claude Code` に作業を渡すときは、毎回この手順で引き継ぐ。

目的は以下の3つ。

- 作業の再開コストを下げる
- 決定事項の取り違えを減らす
- overload や利用制限時でも運用を止めない

---

## 2. 適用場面

このプロトコルは以下の場面で必ず使う。

- `Claude Code` が overloaded、制限到達、または一時停止したとき
- `Codex` に実務を代行させるとき
- `Codex` が行った作業を `Claude Code` に再吸収させるとき
- 日をまたぐ継続作業で、会話文脈に依存したくないとき

---

## 3. 引き継ぎの基本原則

- 引き継ぎは「長い全文ログの転送」ではなく「再開に必要な要点の構造化」を行う
- 必須情報は対象 AI の会話ウィンドウ内だけでなく、必要に応じてリポジトリ内にも残す
- 共有記録に残すべき判断は、会話要約とは別に明文化する
- 不明点は曖昧なまま引き継がず、「未解決」として明示する

---

## 4. 最小 handoff テンプレート

引き継ぎ時は、最低限以下を渡す。

```md
# Handoff

## 目的
- この作業で達成したいこと

## 背景
- なぜこの作業をしているか

## 参照必須
- 読むべきファイル

## 現在地
- 今どこまで進んでいるか

## 決定事項
- すでに確定していること

## 未解決事項
- まだ決まっていないこと

## 触ってよい範囲
- 編集対象と非対象

## 次アクション
- 次にやるべきこと

## 記録先
- 作業後に反映すべきファイル
```

---

## 5. Claude Code → Codex

`Claude Code` から Codex へ渡す場合は、以下を明示する。

- 参照必須ファイル
- 代行してほしい作業範囲
- 触らないでほしい領域
- 作業後にどこへ記録を残すべきか

特に `minutes/`、`docs/digest/`、進行中の未コミット変更については、扱いを明記する。

---

## 6. Codex → Claude Code

Codex から `Claude Code` へ戻す場合は、以下を必ず返す。

- 実施内容
- 変更ファイル
- 判断したこと
- 追加で確認が必要な点
- 次回の開始地点

推奨フォーマット:

```md
# Return Handoff

## 実施内容
- 実際に行った作業

## 変更ファイル
- 変更したファイル一覧

## 判断事項
- 作業中に下した判断

## 残課題
- 未完了または保留の論点

## Claude に引き継ぐ要点
- 次に見るべきポイント
```

---

## 7. 共有記録への反映基準

以下に該当するものは、handoff だけで終わらせず共有記録にも反映する。

- 将来の判断に影響する方針変更
- 設定変更や運用変更
- 他案件にも効くルール化
- 長期継続が前提の未解決論点

反映先の候補:

- `minutes/`
- `docs/digest/_system-state.md`
- 対象案件配下のメモ
- `docs/` の運用文書

---

## 8. 短時間代行の簡略版

短い局所作業であっても、以下の4点は省略しない。

- 目的
- 現在地
- 触ってよい範囲
- 記録先

これだけでも、再開時の事故率を大きく下げられる。

---

## 9. 最終方針

AI を並行運用するときの継続性は、モデル固有の記憶能力ではなく、引き継ぎと共有記録の品質で決まる。

Seep Logos では、handoff を一時的な会話メモではなく、
**組織記憶へ戻るための接続プロトコル**
として扱う。
