# Webデザイナー業務マニュアル

> 対象: Web デザイン担当者（社内スタッフ・業務委託）
> 最終更新: 2026-04-11

---

## 1. Webデザイナーの役割

Webデザイナーの仕事は「見た目を作ること」ではない。
**「目的を視覚で伝えること」**だ。

このページは誰が見るのか。何を感じさせたいのか。何をしてほしいのか。
その問いに答えるために、色・フォント・余白・構造を選ぶ。

装飾は目的を達成するための手段であり、目的そのものではない。

---

## 2. Webデザイナーの仕事一覧

### デザイン設計（コアスキル）

- **ブリーフの読み解き** — 何のためのページか、誰が見るか、何を感じさせるかを言語化する
- **リサーチ・リファレンス収集** — 目的・世界観・ターゲットに近い参考事例を集める
- **カラーパレット設計** — 目的とブランドに合った配色を決め、各色に役割を割り当てる
- **タイポグラフィ設計** — フォント選定、サイズ階層、行間・字間を設計する
- **レイアウト・情報設計** — ページ構成・セクション順・情報の優先度を決める
- **コンポーネント設計** — ボタン・カード・入力欄などの共通部品のスタイルを定義する
- **モーション方向性の決定** — アニメーションの速度・雰囲気の指針を出す

### ドキュメント化（AIとの接点）

- **仕様書（DESIGN.md）の作成** — 設計判断をテキストに落とし込む。これが実装者（AI含む）への指示書になる
- **引き渡しメモの作成** — パターン・使用素材・特記事項を添えて実装者に渡す

### 確認・フィードバック

- **実装確認** — 出力を目的の観点でチェックする
- **修正指示** — 不足があれば仕様書を更新して再依頼する

### 日常業務（案件外）

- 世界の優れたデザイン事例を継続的に見て感覚を養う
- タイポグラフィ・カラー・レイアウトの基礎知識をアップデートする

---

## 3. 案件の進め方

基本は5ステップだ。難しく考えなくていい。
**AIが実装を担うから、あなたはデザインの方向性を決めることに集中すればいい。**

---

### ① 何を作るか把握する

依頼者に確認して、ページの目的・対象ユーザー・使える素材を把握する。
疑問はここで解消する。迷ったまま進まない。

確認リスト：
- [ ] プロジェクト名 / ブランド名
- [ ] ページの目的（LP / サービス紹介 / ポートフォリオ / ティザー など）
- [ ] 対象ユーザー（年齢層・関心・リテラシー）
- [ ] ブランドカラー・既存のデザインルールがあるか
- [ ] 使用する画像・素材の有無
- [ ] 参照したいデザインの方向性（あれば）

---

### ② 「このページが伝えたいこと」を言葉にする

ページを見た人に、何を感じてほしいか。何をしてほしいか。
これをひと言で言えるようにしてから設計に入る。

例：
- 「信頼できる技術力のある企業だと感じてほしい」
- 「このゲームの世界観に引き込まれてほしい」
- 「今すぐ申し込みたいと思ってほしい」

決まったら、それを軸に参考事例を1〜3件集める。
「このページが目指す雰囲気に近いサイトはどこか」で選ぶ。

---

### ③ デザインを決める

②で定めた方向性を視覚に翻訳する。完璧を目指さなくていい。
「なぜこの色・このフォントか」が説明できれば十分だ。

決めること：
- **カラー** — メインカラー・背景色・テキスト色・アクセントカラー
- **フォント** — 本文・見出しに使う書体（目的やブランドの雰囲気に合わせる）
- **レイアウト** — セクションの並び順・情報の優先順位・余白感の大まかな方向性
- **動き** — 速い / 遅い / なめらか / 静止的 など雰囲気だけ決める

細かい値は次のステップで書きながら詰めていける。

---

### ④ 仕様書（DESIGN.md）にまとめて実装者に渡す

決めたことを DESIGN.md というテキストファイルに書き出す。
これが実装者（AIまたは人間のコーダー）への指示書になる。書き方の詳細は §4 を参照。

渡すときは以下のメモを添える：

```
# 引き渡しメモ
- 使用するレイアウトパターン: [例: シネマティック / カードカルーセル など]
- DESIGN.md の場所: [ファイルパス]
- 使用画像: [ファイル名・場所]
- 動きの補足: [③で決めた方向性を一言で]
- 特記事項: [レスポンシブ優先度・対応ブラウザなど]
```

---

### ⑤ 出てきたものを確認して、直す

実装の出力を見て「②で決めた方向性が出ているか」を確認する。
細かい数値より「目的が伝わるデザインになっているか」を問う。

足りなければ DESIGN.md を修正して再依頼する。
修正を繰り返すうちに、DESIGN.md の書き方も自然に上達していく。

---

## 4. DESIGN.md の書き方

DESIGN.md はデザイン設計の成果をまとめた仕様書であり、実装者（AI・人間コーダー）への指示書でもある。
テキスト1枚にまとめることで、Figmaや口頭説明なしに実装を依頼できる。

### 構成（セクション一覧）

| セクション | 目的 |
|---|---|
| 1. Visual Theme & Atmosphere | デザインの目的・雰囲気・空気感を言葉で定義する |
| 2. Color Palette & Roles | 色と役割の対応を hex 値で明記する |
| 3. Typography Rules | フォント・サイズ・ウェイト・行間の体系 |
| 4. Component Stylings | ボタン・入力・カードの具体的なスタイル値 |
| 5. Layout Principles | 余白スケール・コンテナ幅のルール |
| 7. Do's and Don'ts | 推奨・禁止の明文化 |
| 9. Agent Prompt Guide | 実装者が最小限の情報でスタートできる最小セット |

テンプレート: `docs/references/design-md/japan/_TEMPLATE_DESIGN.md`

### §1（Visual Theme）の書き方

**ここが最重要。** §1 が具体的・独自的であるほど、実装の精度が上がる。

良い §1 の条件：

1. **具体的な言葉を使う** —「クリーン」ではなく「石灰岩の白、くすみなし」
2. **なぜその選択をしたかを書く** —「このフォントがブランドの信頼感を作っている」
3. **他と区別できる特徴を強調する** —「太字見出しが主流の中、weight 300 で静かな権威を表現している」

#### 良い例（Stripe の §1 より）

> Stripe uses multi-layer, blue-tinted shadows: `rgba(50,50,93,0.25)` combined with `rgba(0,0,0,0.1)` creates shadows with a cool, almost atmospheric depth — like elements are floating in a twilight sky.

「どんな影か」だけでなく「どう見えるか」「なぜその色か」まで書いている。

#### 悪い例

> シャドウは使用する。カラーは青系。

抽象的すぎて実装者は再現できない。

## 5. 品質チェックリスト

### デザイン設計チェック

- [ ] 「このページが伝えたいこと」がひと言で言えるか
- [ ] 色・フォントの選択に、目的やブランドへの根拠があるか
- [ ] 情報の優先順位がレイアウトに反映されているか
- [ ] 余白が「間」として機能しているか（詰め込みすぎていないか）
- [ ] モーションに過度な均一性がないか（全要素が同じ動きになっていないか）

### DESIGN.md チェック

- [ ] §1（Visual Theme）が具体的で独自性があるか
- [ ] すべての色が hex 値で明記されているか
- [ ] 各色に役割の名前が付いているか
- [ ] フォントにフォールバックチェーンが指定されているか
- [ ] Do's and Don'ts に明確な禁止ルールが書かれているか
- [ ] §9（Agent Prompt Guide）が埋まっているか
- [ ] 参考ブランドのコピーになっていないか（参照は可、転用は不可）

## 6. 参考資料の使い方

### 収集済みブランドの DESIGN.md

```
docs/references/design-md/
├── japan/         # 日本のサービス（22ブランド）
├── international/ # 海外サービス（62ブランド）
└── INDEX.md       # ブランド一覧・タグ索引
```

**参照はするが、転用しない。**
収集した DESIGN.md は「設計手法を学ぶ教材」であり、自分のプロジェクトに貼り付けるものではない。

参照すべき場面：

| 知りたいこと | 参照先 |
|---|---|
| ミニマルで余白を生かした設計 | `linear_DESIGN.md`、`raycast_DESIGN.md` |
| 高品質な §1 の書き方を学ぶ | `stripe_DESIGN.md` |
| 日本語 UI の行間・文字設定 | japan/ 配下全般 |
| 重厚感のあるカラー設計 | `bmw_DESIGN.md`、`ferrari_DESIGN.md` |
| エンタメ・ポップ系の設計 | `spotify_DESIGN.md`、`pinterest_DESIGN.md` |

`docs/references/design-md/INDEX.md` のタグで目的のブランドを絞り込める。
